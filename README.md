# Core — документация

[Открыть мануал](https://nikitakozin.github.io/core-docs/) · [Markdown для агента](content/AGENTS.md) · [Источники и проверки](content/chapters/verification.md)

42 раздела, 82 примера. Документированная версия — **Core v185 от 21 сентября 2026 года**. Оболочка и примеры оформлены штатными классами Core и темой NK, без собственных CSS-правил. Штатные параметры типографики задают масштаб текста оболочки; `--w`, `--h` и `--tr` — размеры и масштаб примеров через API Core.

После `npm run build` откройте `docs/index.html` в браузере или используйте опубликованный мануал по ссылке выше. Сам файл статический; оформление, шрифты и живые примеры требуют сети. Runtime использует CDN `latest`, поэтому его содержимое со временем может отличаться от проверенной версии.

Тёмная боковая навигация сохраняет группы и подразделы; шапка с поиском закреплена. На экранах до 997 px разделы открываются поверх статьи. Меню закрывается по Escape, нажатию на фон или выбору раздела. Поиск доступен по ⌘K / Ctrl+K.

У примера семь кнопок ширины: Auto, 390, 720, 721, 997, 998 и 1200 px. Код раскрывается под результатом; обычные фрагменты инструкций видимы сразу. Тема, ввод и выбранная ширина сохраняются при переключении глав в открытом мануале.

## Редактирование

- `content/chapters/` — тексты глав; индекс классов генерируется при сборке.
- `content/reference/examples.json` — разметка и JavaScript примеров. При изменении примера обновите соответствующий блок Markdown; проверка сверяет их.
- `content/reference/` — JS-контракты и метаданные проверенной версии: URL, размеры и SHA-256. Копии исходного Core в репозитории не хранятся.
- `content/chapters.json` — порядок, группы и короткие названия разделов.
- `content/viewer/app.js` — поведение оболочки, без собственного оформления.
- `tools/` — сборка и инспекция CDN; `tests/` — проверки.
- `docs/` — полностью генерируемый результат, исключённый из Git: HTML, публичные Markdown и JSON. Не редактируйте его вручную.

Node.js 22 или новее нужен только для разработки. Зависимости закреплены в lockfile: Marked разбирает Markdown, PostCSS и selector-parser строят справочники, Playwright проверяет настоящий браузер. Runtime не использует npm-пакеты.

```sh
npm ci
npm run build
npm test
npx playwright install chromium
npm run test:browser
npm run test:layout
npm run serve
```

Локальный адрес: `http://127.0.0.1:4173/`. Тесты используют Chromium, совместимый с закреплённым Playwright. Команда установки браузера нужна один раз после `npm ci`. Сборка и проверки требуют сети: справочники собираются из четырёх CSS-файлов CDN v185 с проверкой SHA-256, контрактные тесты сверяют 32 ответа v185 с манифестом и проверяют доступность 32 файлов latest. Изменение latest явно выводится в диагностике; оно не обновляет документированную версию автоматически. Недоступность CDN или неверный хеш v185 останавливает сборку/проверку.

Браузерные тесты проверяют мануал с настоящим latest, включая iframe и ESM. Отдельная проверка точных CSS-контрактов документации загружает v185 с того же CDN. На 23.09.2026 каталог содержит v190, а latest отличается от описанного v185; полная совместимость новой версии этим прогоном не подтверждается.

`npm run test:layout` проверяет компактность шапки, неподвижность боковой панели, меню без сдвига статьи, клавиатурный фокус и структуру примеров на граничных ширинах. Визуальную аккуратность дополнительно проверяйте по парным снимкам: функциональный прогон её не доказывает.

`npm run build` очищает `docs/`, копирует публичные исходники, генерирует каталоги классов/токенов и индекс классов из CDN, затем собирает HTML. В Git коммитятся только исходники. GitHub Actions выполняет ту же сборку и проверки перед публикацией Pages. Служебные инструменты и исходник просмотрщика в артефакт не копируются; JavaScript просмотрщика встроен в HTML.

`python3 tools/inspect-cdn.py --audit` читает и хеширует текущие JS-файлы CDN без сохранения локальных копий. Проверка сетевых отказов мануала входит в обычный браузерный прогон.

## Обновление Core

Проверять новые версии **только по запросу владельца**:

```sh
npm run check:upstream
```

Команда ничего не меняет: сравнивает каталог версий, список файлов latest и SHA-256 каждого файла с манифестом. Код выхода: 0 — совпадает, 2 — есть изменения, 1 — ошибка проверки. Принятие новой версии и изменение манифеста/документации выполняются отдельно, после анализа изменений. Обычные сборки и проверки не обновляют эту базу автоматически.

Исходный комплект v182 сохранён без изменений в коммите `e9de771`. Манифест содержит его контрольные суммы и результаты сверки v182 → latest/v185. Сайт автоматически публикуется через GitHub Pages после каждого push в `main`: https://nikitakozin.github.io/core-docs/.
