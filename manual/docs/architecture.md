# Архитектура: пять типов правил

[Оглавление](../README.md) · [Правила агента](../AGENTS.md)

## 1. Основания

`core-row`, `core-col`, `core-grid`, `core-section`, `core-slider`, `core-card`, `core-button`, `core-input` включают соответствующее поведение или оформление. У основания есть свойства по умолчанию. Например, `core-row` — уже flex-контейнер с переносом, а не просто метка для JS.

## 2. Модификаторы

`core-grid-3c` задаёт число колонок через `--grid-cols`; без `core-grid` он не превращает элемент в grid. `core-button-l` меняет параметры уже существующей кнопки. `core-abs-top-right` задаёт координаты, но без позиционирующего основания элемент остаётся в обычном потоке.

Исключения существуют: `core-badge-button` имеет общие базовые правила с `core-badge`, поэтому может использоваться сам. Не превращайте принцип «основание + модификатор» в выдуманное требование ко всем именам.

## 3. Утилиты и рабочие параметры

`core-g-8x` меняет `gap`, записывает `--g` и передаёт `--parent-g` непосредственным детям. `core-p-8x` задаёт `--p`, а отдельное семейство селекторов потребляет его как padding. `core-color-blue:700` задаёт вход цветового вычисления. То есть «один класс — одно свойство» здесь не универсальное правило.

## 4. Контекстные адаптеры

`core-content` форматирует обычные HTML-теги внутри. `core-input-box` снимает часть самостоятельного оформления вложенных контролов. `core-actions-box` убирает внутренние скругления у соседних действий. Это отдельный механизм — **применение селектора к потомку**, а не наследование свойства.

## 5. Тематические и семантические токены

Слой основы: `--x`, `--icon-x`, `--rem-base`, исходные цвета и метрики шрифтов. Слой шкал: `--s-*`, `--i-*`, `--f-s-*`, `--b-r-*`. Семантика: фон, текст, акцент, ошибка. Компонентный слой: `--theme-btn-*`, `--theme-input-*`, радиусы карточек и бирок. Рабочий слой: `--p`, `--g`, `--tc-result`, `--parent-g` и другие промежуточные параметры.

Не все переменные автора объявлены публичным контрактом. В этом руководстве «настраиваемый токен» означает параметр, применение которого прослеживается в CSS; внутренние вычислительные переменные выделены отдельно.

## Как читать композицию

```html
<section class="core-card core-col core-g-8x core-p-12x core-bg-surface">
  ...
</section>
```

`core-card` — поверхность и позиционирующий контекст. `core-col` — вертикальный flex. `core-g-8x` — 16 px между детьми при базовой шкале. `core-p-12x` — 24 px внутри. `core-bg-surface` — явный семантический фон; в этом случае он повторяет базовую роль карточки и может быть опущен.

Порядок токенов в атрибуте `class` не устанавливает приоритет CSS. Приоритет задают специфичность, важность деклараций и порядок правил в stylesheet. Принятая здесь запись «основание → вариант → размер → компоновка → утилиты → адаптив» служит чтению, не управлению каскадом.

## Что не является Core

Классы с префиксом `app-` в примерах — явные расширения проекта. HTML-атрибуты `type`, `required`, `disabled`, `aria-*`, `contenteditable` — платформенные возможности. Названия рецептов вроде «панель поиска» не означают существование класса `core-search-panel`. Не переносите такой мысленный ярлык в код.
