# Работа над CORE docs

## Назначение

Сопровождать документацию Core: HTML-мануал, Markdown-справочник для агента и примеры. Не менять исходный фреймворк и сторонние проекты в рамках задачи документации.

## Локальный workspace

Если репозиторий открыт как `CORE/github`, сначала прочитайте `../AGENTS.md` и `../project-kb/AGENTS.md`, затем настройки и текущую задачу в `../project-kb`. Эти материалы принадлежат локальному workspace и не входят в репозиторий.

При самостоятельном clone используйте этот файл и явную задачу пользователя. Отсутствие внешней базы знаний не должно ломать будущую сборку или просмотр документации.

## Правила содержания

- Источник истины — конкретные исходники Core и проверенное поведение примеров.
- Не придумывайте классы, API и ограничения по аналогии с названиями.
- Отличайте штатную возможность, составной рецепт и дополнительный CSS/JS примера.
- Согласуйте HTML и Markdown; ограничения описывайте рядом с механизмом.
- Подключайте штатные ассеты Core из `https://cdn.sdelal.tech/core/latest/`; фиксируйте снимок, по которому проверяете документацию. Не считайте CDN и локальный архив одинаковыми без сверки.
- Не переносите неподтверждённые выводы о Core из старого сравнения с NKUI как установленные факты.
- Пишите по-русски, кратко и предметно. Точные имена API и классов сохраняйте.

## Текущее состояние

Комплект мануала ещё не импортирован. Команды сборки, проверки и его внутренняя структура определяются после инвентаризации реальных файлов. Не добавляйте зависимости и инфраструктуру CI заранее.

Эти инструкции предназначены автору документации. Будущая точка входа для агента, который строит интерфейс на Core, относится к самому комплекту мануала и создаётся при его переносе.

## Проверка изменений

Для текста и инфраструктуры: проверить относительные ссылки, подготовленный diff и `git diff --check`. Для поведения примеров понадобятся проверки в настоящем браузере на соответствующих исходниках Core. Отчёт предыдущего исполнителя не заменяет собственную проверку.
