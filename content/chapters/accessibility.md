# Доступность, совместимость и интеграция

[Оглавление](../README.md) · [Правила агента](../AGENTS.md)

## Ответственность слоёв

CSS оформляет состояния и может поддержать взаимодействие, но не устанавливает бизнес-логику и семантику интерфейса. У каждого действия должны быть подходящий HTML-элемент и доступное имя. У кнопки только с иконкой — aria-label или доступный текст; у поля — label; у ошибки — связь с полем и текстовое объяснение. Цвет без текста не является достаточным сообщением о статусе.

У `button` внутри формы явно задавайте type. Disabled задавайте нативным атрибутом там, где это возможно. Для ссылки `aria-disabled` само по себе не предотвращает переход: такое поведение требует прикладной логики. Pointer-events none не отключает клавиатуру.

## Фокус и hover

Core содержит оформление `:focus-visible`, а hover-trigger учитывает фокус в поддереве. Это полезная база, но она не доказывает доступность любого составного виджета. Изменение z-index на фокусе, маски и overflow могут влиять на визуальное положение рамки. Проверяйте Tab, Shift+Tab, Enter и Space на реальной разметке.

`core-target:show` прячет прозрачностью, а `core-ghost` не равнозначен inert. Скрытые интерактивные дети требуют отдельной проверки. Смысловые действия не должны существовать только на hover. Не полагайтесь на hover-предпросмотр при работе с touch.

## Форма

Нативные checkbox/radio внутри label сохраняют браузерную модель выбора. Не заменяйте input на span ради удобства стилизации. У радиокнопок одной группы должны совпадать name и различаться value. Placeholder — не замена label. Подсказки и ошибки связывайте через aria-describedby; aria-invalid выставляйте согласно действительной проверке.

Контракты модулей разобраны в [FormManager](js-form.md) и [FieldManager](js-field.md). Их хеши при обновлении не изменились. Не переносите на них обещания нативной валидации, масок или обработки ошибок, которые не подтверждены соответствующим разделом.

## Движение и контраст

В Core CSS правило `prefers-reduced-motion` относится к scroll-hint; глобального отключения всех анимаций нет. Для собственных сценариев учитывайте системную настройку: E58 переключает класс анимации через matchMedia, MotionManager поддерживает reduced motion. Не отключайте все transform: они используются и для позиционирования. Оболочка мануала не добавляет собственных анимаций.

Набор цветовых утилит разрешает сочетания, которые могут иметь недостаточный контраст. Ни наличие тёмной темы, ни суффикс оттенка не гарантируют приемлемое соотношение контраста. Для каждого реального текста/фона проверяйте вычисленные цвета, включая disabled, hover, opacity и вложенные полупрозрачные поверхности. Данный комплект не является аудитом WCAG.

## Совместимость

Core использует современные CSS-механизмы. Наличие современного CSS-синтаксиса не устанавливает поддерживаемую матрицу браузеров; проверяйте целевые версии проекта. Firefox, Safari, iOS WebView и старые Chromium в этой работе не запускались.

Особенно важны CSS nesting, :has(), color-mix/OKLCH, @property, mask, dynamic viewport units, container query units и corner-shape. Поддержка corner-shape улучшает форму скруглений; без неё предусмотрена иная геометрия. Отсутствие CSS nesting затрагивает гораздо больше правил и не является просто косметическим fallback.

## Интеграция в существующий проект

При интеграции учитывайте границы reset и метрик: базовые правила выбирают элементы с Core-классами, а типографические метрики применяются внутри `core-solo` или области `core-theme-*`. v190 больше не устанавливает глобальный font-size на html через `--rem-base`, но регистрации коротких custom properties остаются общими для документа. Сравните computed styles и вид старых компонентов до и после подключения.

Iframe даёт более сильную изоляцию документа, но меняет коммуникацию, высоту, фокус и адаптивный viewport. Shadow DOM не следует объявлять проверенным способом подключения без отдельного прототипа. Для нового интерфейса на Core проще использовать цельную систему токенов, чем смешивать несколько конкурирующих reset и компонентных библиотек.

## Приёмочный минимум конкретной композиции

Проверьте светлую/тёмную тему, 998/997 и 721/720 px, длинный русский текст, пустые данные, заполненные и disabled-поля, клавиатуру, видимый фокус, увеличение масштаба, reduced motion и отказ загрузки шрифта. Для диалогов дополнительно проверяются фокус и фон; для динамического DOM — повторное подключение поведения и очистка ресурсов.
