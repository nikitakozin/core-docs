# Порядок работы агента и Harness

[Оглавление](../README.md) · [Правила агента](../AGENTS.md)

## Подключить к проекту

Положите весь каталог документации, например, в `docs/core/`. В существующий корневой `AGENTS.md` добавьте один блок, не удаляя проектные инструкции:

```md
## Интерфейсы на Core

Для задач интерфейса сначала прочитай docs/core/AGENTS.md.
Все оригинальные ассеты Core подключай с https://cdn.sdelal.tech/core/latest/.
Не читай весь HTML-мануал: используй тематические Markdown-файлы.
```

Сам `AGENTS.md` — инструкции для агента, а не исполняемый файл. После подключения задайте реальную ограниченную задачу в существующем приложении. Путь `docs/core/` в примере замените на фактическое место документации.

## Первый пробный запрос

```text
Прочитай docs/core/AGENTS.md. Собери экран реестра проектов на Core в текущем
приложении: заголовок, поиск, фильтр статуса, таблица, пустое состояние и форма
создания. Используй существующие API, маршруты и способ рендера проекта.
Оригинальные ассеты — только https://cdn.sdelal.tech/core/latest/.
Не добавляй React, сборщик или другую UI-библиотеку без необходимости.
Покажи адаптацию на 390/720/721/997/998/1200 px; клавиатуру, ошибки и длинный текст.
Отдели собственный CSS/JS от Core. Новые непроверенные JS API не выдумывай.
В конце перечисли изменённые файлы, фактические проверки и оставшиеся ограничения.
```

## Читать выборочно

Сначала [архитектуру](architecture.md), [наследование](inheritance.md) и только необходимые компоненты. [Индекс классов](https://nikitakozin.github.io/core-docs/chapters/class-index.md) содержит проверенные по тексту источника имена из примеров, но не все классы Core. `reference/examples.json` хранит HTML/CSS рецептов, `reference/tokens.json` — документированные значения. Пути `reference/` считаются от каталога комплекта.

## Порядок реализации

Определить семантику, поток, состояния и существующие механизмы приложения. Выбрать Core-основания, размеры и варианты, затем отступы и адаптивность. Проверить прямых детей, соседей, контекст и переменные. Новый `app-*` CSS допустим только для недостающей прикладной функции, например таблицы-карточек E68; весь такой CSS должен быть виден рядом с примером.

Обычный native HTML и код приложения предпочтительнее выдуманного вызова модуля. Когда нужен JS Core, сначала прочитать текущий файл и его зависимости с CDN, затем отдельно проверить минимальный сценарий. [Покрытие и порядок чтения JS](javascript.md).

## Проверять результат, а не только наличие классов

Тестируйте страницу с настоящим CDN в браузере проекта. Ошибка загрузки CDN — блокер визуальной проверки, не повод подменять Core тестовым CSS. Проверить переходы брейкпоинтов, длинный текст, ошибку/пустое состояние, клавиатуру, фокус и повторный рендер компонента. При глобальном изменении темы расширьте визуальную регрессию.

При недоступном источнике точно укажите непроверенную часть и продолжайте независимую работу. Не объявляйте файл изученным по названию или HTTP-статусу. Для утверждения об отсутствии ошибок нужны фактические результаты, а не старый отчёт из документации.
