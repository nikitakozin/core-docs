# Источники и проверки

[Оглавление](../README.md) · [Правила агента](../AGENTS.md)

## Проверенная версия

Текущие версия, дата, URL, размеры и SHA-256 закреплены в [манифесте](../reference/source-manifest.json). При обновлении 23.09.2026 сопоставлены 32 файла v185, 32 файла v190 и 32 ответа latest. Файлы предыдущей версии сначала проверены по сохранённым хешам. Копии исходного Core в репозитории не хранятся: сборка и проверки читают CDN.

У 29 файлов latest и v190 совпали байты. `.readme.html`, `importmap.js` и `importmap.min.js` отличаются адресами канала; после замены только этих адресов содержимое совпало. Это результат на дату проверки, не постоянное тождество latest и версии.

Десять функциональных JS-модулей совпали с ранее разобранной версией. Их контрактные описания сохранены; влияние нового CSS на компоненты проверяется отдельно. Из тем изменился только `theme-ss.css` и его минифицированный вариант.

## Что изменилось в v190

- Режимы цвета выбираются классами `core-theme-light/dark`; data-theme больше не является переключателем CSS.
- Интерфейсная шкала использует `--f-s-base` вместо глобального html/rem. Старый `--rem-base` в теме NK не меняет новую шкалу.
- Размеры иконок числовые: прежний `core-icon-m` заменяется на `core-icon-8x`; маска задаётся на элементе через `--im-img`.
- Grid использует `--grid`; неравные готовые сетки удалены. Их примеры задают треки переменной на обёртке: сетка наследует их и переопределяет адаптивным классом на узком экране.
- Удалены `core-form-item`, `core-form-item-inline`, `core-label`: примеры используют композицию row/col, gap и текстовых классов.
- Таблицы используют `core-table-border-x/y/head` и общую обёртку `core-x-scroll`. Старые специализированные обёртки удалены.
- Основание заголовков — точные `core-h1` … `core-h6`; адаптация размера выполняется t/m-текстовыми классами. Удалены старые `core-text-muted*`, `core-text-b`, `core-text-inverse`, `core-popup-zero`, `core-overflow-none` и адаптивные border-none.
- Исправлены t/m-алиасы позиционирования, fallback направленного padding и границы disabled checkbox/radio. `--b-r`, `--t`, `--b` зарегистрированы как ненаследуемые; радиус контролов светлой SS увеличен до `--b-r-8x`.
- Reset, области метрик, row/col-reverse, скроллбары и порядок правил переработаны. У slider есть `core-slider-scrollbar`. Устаревшие анимационные defaults JS остаются отдельным ограничением.

Подробности и действующие ограничения — в [реестре](pitfalls.md). Предыдущие состояния документации доступны в Git-истории.

## Справочники и сборка

PostCSS разбирает четыре CSS-файла документированной версии после проверки SHA-256. [Классы](https://nikitakozin.github.io/core-docs/reference/classes.json), [токены](https://nikitakozin.github.io/core-docs/reference/tokens.json) и [индекс](https://nikitakozin.github.io/core-docs/chapters/class-index.md) генерируются автоматически. Каталоги показывают исходные декларации, строки и области, а не вычисленные default. Счётчики находятся в самих каталогах.

Редактируемые источники находятся в `content/`: главы, JSON примеров и метаданных, код просмотрщика. `npm run build` заново создаёт игнорируемый `docs/`: 42 главы, 82 примера, HTML и JSON. Оформление задаётся штатным Core; собственных CSS-правил нет. Версия в интерфейсе и метаданных сборки берётся из одного манифеста.

## Текущие проверки

`npm test` проверяет сравнение версий, целостность Markdown/JSON, публичные ссылки, классы примеров, отсутствие собственного CSS, все SHA-256 документированной версии и доступность latest. `npm run test:browser` проверяет загрузку 82 примеров, выбранные действия JS, действительную смену цветов, сохранение ввода, границы адаптивности, ошибки CDN и повторную загрузку. Точные CSS-пробы загружают версию из манифеста. `npm run test:layout` проверяет оболочку, навигацию и мобильное меню. Все сетевые проверки используют настоящий CDN.

Один успешный запрос CSS не доказывает оформление компонента. Для изменений тем, сеток и общих метрик нужны вычисленные размеры, действия и визуальный просмотр. Отчёты прошлых версий не считаются результатом текущего прогона.

Новые версии проверяются только по запросу владельца. `check:upstream` возвращает код 2 при изменениях. `docs:diff -- --to latest` один раз выбирает конкретную версию и готовит отчёт в `work/core-update/`, не меняя принятый манифест. Общие и непокрытые изменения явно отмечаются. Порядок принятия — в [инструкции автора](https://github.com/nikitakozin/core-docs/blob/main/UPDATE.md).

Обычная сборка не принимает новую версию. Недоступность CDN или изменённый SHA-256 версии останавливает публикацию. Расхождение изменяемого latest показывается диагностикой; дата его последней сверки выводится отдельно от версии документации.

## Границы достоверности

Инициализация всех примеров не означает перебор всех состояний каждого компонента. Проверки выполняются в Chromium; Safari, Firefox и скринридеры не проверялись. Шрифты загружаются штатной темой, но все платформы и начертания не покрыты. Минифицированные файлы проверены по хешам; их семантическая эквивалентность исходникам не заявляется. Сетевые сбои могут остановить проверки при неизменной документации.
