## Проверенный снимок

21.09.2026 скачаны 32 файла из `latest/` и 32 файла из `v185/`: CSS, три темы, десять функциональных JS-модулей, importmap, их минифицированные варианты, шаблон и readme. Снимки сохранены в `upstream/`; SHA-256, размеры и исходные адреса — в [манифесте](../reference/source-manifest.json).

У 29 файлов latest и v185 одинаковые байты. `.readme.html`, `importmap.js` и `importmap.min.js` отличаются адресами канала. Нельзя считать latest и v185 полностью одинаковыми.

Все 17 исходников v182, перечисленных в старом манифесте, скачаны повторно и совпали с его SHA-256. По сравнению с v182 изменились CSS, importmap и readme. Десять функциональных JS-модулей и три темы не изменились. Их подробное описание из первоначального аудита сохранено; новые ограничения совместимости JS/CSS отмечены отдельно.

## Что изменилось в v185

- Иконки `shevron` переименованы в `chevron`; именованные размеры задаются на элементе.
- Подчёркивание шапки таблицы: `core-table-head-underline`.
- Адаптивные ограничения роста: `t-core-nogrow/noshrink`, `m-core-nogrow/noshrink`.
- Добавлен `--s-170x`; исправлены общий селектор заголовка, цвет radio-group и несколько opacity-деклараций.
- Анимации используют `core-animate:*`. CollapseManager, SliderManager и обработчик копирования FieldManager всё ещё используют старые имена. Для первых двух доступны настройки; особенности FieldManager описаны в его разделе.
- У padding удалён fallback `0`; у позиционирования исправлены разделители, но смешаны некоторые t/m-алиасы.
- Карта latest теперь ведёт на latest.

Подробности, включая оставшиеся проблемы, — в [реестре ограничений](pitfalls.md).

## Справочники и сборка

PostCSS разбирает четыре CSS-файла снимка: **2600 явных классов, 481 имя custom properties, 19 регистраций @property**. Каталоги сохраняют файл, строку и область действия. Это исходные декларации, а не обещание допустимости каждого вычисленного значения.

HTML собирается из 42 Markdown-глав и 82 примеров. Оформление оболочки и примеров полностью задаётся Core и темой NK: собственных CSS-правил нет. Штатные переменные `--w`, `--h` и `--tr` управляют размером и масштабированием iframe. Действия оболочки реализованы отдельным vanilla JS.

## Текущие проверки

В репозитории находятся воспроизводимые проверки `npm test`, `npm run test:browser` и `npm run test:layout`. Они проверяют целостность источников, отсутствие собственного CSS, соответствие примеров Markdown, работу оболочки и выбранные действия в живых iframe. Основной браузерный прогон получает **неизменённые байты снимка** вместо сетевых ответов CDN; это не имитация API Core. Проверяются ширины 390/720/721/997/998/1440 px, сохранение ввода при смене темы и главы, reduced motion, ошибка CDN и повторная загрузка.

Оболочка дополнительно проверена на сохранение компактной шапки и боковой навигации при прокрутке, мобильное меню без сдвига статьи, закрытие по фону/Escape/выбору раздела и удержание клавиатурного фокуса. Парные снимки исходного и восстановленного мануала сравнивались отдельно: начало главы, пример, раскрытый код, мобильное меню и тёмная тема. Эти проверки не заменяют оценку остальных компонентов Core.

Отдельная команда `node tests/browser.mjs --live` проверяет загрузку оболочки и ESM-примера через реальный CDN. `npm run check:upstream` заново сравнивает каталог, список файлов и все SHA-256, ничего не изменяя. Последняя проверка 21.09.2026 не обнаружила изменений относительно снимка.

Старые отчёты о 35 CSS-, 26 UI- и 74 JS-проверках сохранены в исходном коммите v182. Эти числа не являются результатом текущего прогона и не суммируются с новыми проверками.

## Границы достоверности

Запуск всех примеров не означает перебор всех состояний каждого компонента. Воспроизводимый браузерный стенд использует Chromium; Safari, Firefox и скринридеры не проверялись. В тестах снимка внешние шрифты отключены; отдельная сетевая проверка не является полной проверкой всех шрифтов и платформ.

Не проверяются реальные серверные endpoint, Telegram SDK, успешное сохранение FormManager в localStorage/cookie и полная эквивалентность минифицированных файлов. Фреймворк не исправляется скрытыми патчами мануала. Latest остаётся изменяемым; новые версии проверяются только по запросу владельца.
