# Контентная область: статьи и HTML из редактора

[Оглавление](../README.md) · [Правила агента](../AGENTS.md)

## Назначение

`core-content` позволяет оформить семантическую статью без присваивания класса каждому абзацу и заголовку. Он задаёт правила для p, h1…h6, figure, pre/code, blockquote, списков, таблиц, ссылок, кнопок и ряда текстовых элементов.

Область подходит для выводимого редактором HTML, описаний, документации и содержательных блоков. Это **не песочница безопасности**: недоверенный HTML по-прежнему нужно очищать. CSS не защищает от скриптов, опасных URL и обработчиков событий.

## Ритм

Абзацы получают вертикальные интервалы и max-width 750 px; у первых абзацев и заголовков убирается верхний margin. Заголовки используют свою шкалу `em`, собственные интервалы и line-height. Figure, pre, blockquote и таблицы получают крупные межблочные интервалы. Если нужная ширина статьи меньше, ограничьте внешний контейнер, не меняя каждый p.

`core-content-s`, `core-content-m`, `core-content-l` — изменения локального масштаба. Используйте вместе с `core-content`. Вложение масштабирующих областей на `em` может перемножать размеры. Интерфейсные элементы внутри при этом могут явно назначать свои `rem`-размеры и не следовать всему масштабированию.

## Контент рядом с интерфейсом

Core содержит правила, обнуляющие margins у потомков внутренних row/col/grid/section/slider/split внутри контентной области. Это помогает вставлять UI в статью, но создаёт зависимость от вложенности. Перенос абзаца внутрь `core-col` способен изменить ритм без изменения самого p.

Обычный `<button>` внутри `core-content` получает оформление даже без `core-button`. Это удобно для контента, но не означает полного тождества всех состояний и модификаторов двум способам включения. Для UI-рецептов используйте явное основание.

## Код, цитата, изображение

Inline code и pre имеют собственные фон, размер и overflow. Pre не переносит код как обычный текст. Blockquote — оформленный блок с padding; он остаётся цитатой по HTML-смыслу. Для figure без собственного класса есть отдельное правило, поэтому добавление любого класса меняет точное совпадение этого селектора.

`h6` в рассмотренном фрагменте берёт `--f-s-xs` в rem, тогда как старшие заголовки основаны на content-em-токенах. Не обещайте равномерное относительное масштабирование всех шести уровней.

### E27. Содержательная статья с небольшой UI-вставкой

Текст форматируется контекстом, панель действий — явными UI-классами. Исходный CSS может менять margin потомков панели.

```html
<article class="core-content">
  <h1>Правила проекта</h1>
  <p>Документ фиксирует договорённости и помогает команде работать с одной версией информации.</p>
  <h2>Материалы</h2>
  <p>Названия файлов должны объяснять содержание. Для переменных используем <code>--color-accent</code>.</p>
  <blockquote>Решение считается принятым после фиксации в журнале проекта.</blockquote>
  <div class="core-row core-g-4x">
    <button type="button" class="core-button core-button-primary">Открыть журнал</button>
    <button type="button" class="core-button">История</button>
  </div>
</article>
```

### E28. Локальный масштаб контента

Сравнивается локальное em-масштабирование content, а не изменение всего root-размера.

```html
<div class="core-grid core-grid-2c m-core-grid-1c core-g-12x">
  <article class="core-content core-content-s"><h2>Компактный текст</h2><p>Для пояснений внутри интерфейса.</p></article>
  <article class="core-content core-content-l"><h2>Крупный текст</h2><p>Для короткого вводного блока.</p></article>
</div>
```
